# Техническое задание: Домашняя система иерархического хранения (Инвентаризация)

## Глобальные ограничения проекта
- **Стек:** Go (Golang), чистый `net/http`,  без использования СУБД. На Go в папке проекта создать файл с собственной базой данных. Хранение фотографий в отдельных папках (вне базы данных, в базе только ссылки).
Все ссылки в базе должны иметь относительный путь, для возможности переноса или бекапирования всей папки.
- **Среда:** Работает исключительно в ЛОКАЛЬНОЙ сети (дома/в гараже).
- **Безопасность:** Авторизация, пользователи и сессии НЕ нужны. Доступ открыт для всех в локальной сети.
- **Интерфейс:** Веб-приложение с адаптивной версткой (удобно как со смартфона, так и с ПК).  

---

## 1. Архитектура данных и иерархия мест хранения
Система использует жесткую иерархическую структуру мест хранения:
1. **Локация** (Верхний уровень: Дом, Гараж, Дача)
2. **Стеллаж / Мебель** (Шкаф, Комод, Верстак)
3. **Полка** (Полка 1, Полка 2 — отсчет снизу)
4. **Коробка / Контейнер** (Коробка 1, Органайзер А)

### Система маркировки (Этикетки):
Каждый элемент иерархии имеет уникальный генерируемый текстовый код (адрес) для печати/наклеивания.
- **Формат:** `[Локация]-[Стеллаж]-[Полка]-[Коробка]` (например: `д-ш1-п3-к1` -> Дом, Шкаф 1, Полка 3, Коробка 1).
- Если вещь лежит просто на полке без коробки, адрес укорачивается: `д-ш1-п3`.

### Структура карточки вещи (Item):
- `id` (UUID или Serial, первичный ключ)
- `name` (Название вещи, обязательное)
- `description` (Описание)
- `sku` (Артикул)
- `barcode` (Штрихкод: ручной ввод или автогенерация системой)
- `location_id` (ID места хранения, связывает вещь с финальной точкой в иерархии)
- `photos` (Массив путей к файлам фотографий на сервере)
- `parameters` (JSONB-поле в PostgreSQL):
  - `weight_kg` (Масса в кг)
  - `dimensions_mm` (Габариты: длина, ширина, высота)

## 2. Функциональные требования к веб-интерфейсу

### Главная страница (Поиск):
- По центру страницы расположен **глобальный живой поиск**.
- Поиск должен работать по вхождению части строки (LIKE `%запрос%` или ILIKE) в любом месте карточки: по названию, артикулу, штрихкоду или тексту из описания. 
- Результаты поиска выводятся в виде плитки или списка карточек с миниатюрами фото.

### Левое навигационное меню (Панель управления):
Меню должно содержать фиксированный набор функций:
1. **Добавить вещь** (Форма создания карточки)
2. **Удалить вещь** 
3. **Переместить вещь** (Быстрая смена `location_id` для вещи/группы вещей)
4. **Добавить место** (Создание нового элемента иерархии: локации, шкафа, полки или коробки)
5. **Удалить место** (С проверкой: нельзя удалить место, если в нем лежат вещи)
6. **Переместить место** (Возможность переместить коробку со всеми вещами на другую полку/в другой шкаф). Подключить возможность пееретаскивания drag-ndrop.
7. **Показать место** (Дерево иерархии. При клике на полку или коробку отображается список всех хранящихся там вещей)

## 3. Требования к работе с медиа (Фотографии)
- Система должна поддерживать загрузку **нескольких фотографий** для одной карточки товара.
- **Мобильная версия:** При нажатии на кнопку добавления фото интерфейс должен запрашивать доступ к нативной камере смартфона (атрибут `capture="environment"` в HTML-инпуте), позволять сделать снимок и сразу отправлять его на бэкэнд без предварительного сохранения в галерею.
- **Десктопная версия (ПК):** Стандартный выбор файлов через проводник или drag-and-drop.
- На бэкэнде (Go) файлы сохраняются в локальную папку на сервере (например, `./uploads/`), а в базе данных хранятся только относительные пути к ним.

## 4. Алгоритм генерации кода для ИИ (Инструкция для Continue)
При реализации модулей строго следуй правилам:
1. Сначала сгенерируй файл собственной базы данных для `locations` (с self-referencing связью для иерархии) и `items`.
2. Напиши Go-структуры в пакете `models` с тегами `json` и `db`.
3. Реализуй методы обработки изображений (сохранение на диск, генерация уникальных имен файлов).
4. Напиши HTTP-эндпоинты для CRUD операций (обработки запросов из левого меню).
5. Фронтенд реализуй на чистом HTML/CSS/JS (Vanilla JS, Fetch API), без использования тяжелых фреймворков вроде React/Vue, так как проект разворачивается локально.
